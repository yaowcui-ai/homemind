# D1：多Agent全栈方案与评测契约

日期：2026-10-28，Asia/Shanghai。状态：设计交付，D2—D5尚未实现。用户要求同时保留AI全栈、评测调优和AI产品能力。D1不改业务代码、不调用真实模型、不使用C2剩余额度；既有v0.4.0/M4正常路径保留。

## 1. 产品价值与可证伪假设

面向同一生活任务中的取舍：按时达到温度、尽早达到目标、降低同范围仿真能耗、保留用户指定设备。舒适在本期只代理为“独立温度读数首次达标的仿真分钟”，不推断睡眠、噪声或真实体感。

已有证据：[C2](../../product/product-c2-evaluation.md)证明风速是关键控制变量；本轮另用现有引擎做0模型请求对照，20分钟low26.8℃/auto26.0℃，60分钟两者26.0℃但low550.050Wh/auto850.050Wh。只是固定仿真假设，不是预测工具或多Agent已实现，也不外推现实节电。[本轮证据](../../../evaluation/results/product-d1-tradeoff-20261028.json)。

假设HD1：分开的舒适/能耗建议能提高带范围例外的多目标需求处理质量。HD2：质量收益能抵偿额外模型调用、等待及失败点。必须允许两假设不成立。有限候选的数值选优本身可用确定性程序完成，这部分不能包装成多Agent独有能力。

| 方案 | 价值/代价 | 本期选择 |
| --- | --- | --- |
| 增强单Agent+相同预测工具 | 改动小、调用少，能直接使用完整事实 | 必须实现，作为主对照S1；收益不足时保留为默认 |
| 舒适/能耗专家并行+协调Agent | 角色分别检查不同目标、提出理由，增加调用/上下文/故障点 | 实验M，验证HD1/HD2；不预设优于S1 |
| 多个Agent各自直接控制设备 | 多写入源/冲突/难核验 | 不采用；所有角色只读，程序统一执行 |

规划+审查两角色可作为后续消融，暂不同时引入第二套多Agent架构。三角色方案复用原总体设计的舒适/节能/协调方向。

## 2. 首版范围与用户流程

仅对单房间回家温度/期限与仿真能耗权衡提供实验入口。一个被明确定位的空调、至多一个窗帘；设备重名/多实例未定位先问。其他灯/房间保持原样，保留/保护是硬约束。多房间温控、预约分时开关、分时电价、湿度/噪声、自动重规划、SSE、硬件控制不纳入本期。

“舒适优先”定义：满足截止目标的候选中先按首次达标分钟，再按同范围能耗排序；“能耗优先”：先按同范围能耗，再按首次达标分钟。用户明确温度和期限均为硬条件，不能为了省电升高目标或延长期限。用户只说“兼顾”但没有偏好时澄清；明确指定low则候选不含auto。

流程：登录 → 标准助手或“方案权衡（实验）” → 自然语言/明确偏好与保留项 → 必要澄清 → 展示理解到的温度/期限/范围/硬约束、候选预测与取舍 → 用户确认 → 确认前重读版本 → 统一执行 → 实际读回及截止时刻核验 → 历史。预测成功不表示已执行或实际达标。

标准简单关灯沿用当前入口。D首版不做额外LLM复杂度路由；用户显式选实验。增强单Agent S1在同一流程可用于对照，普通首页不展示评测脚本/预算账本。

## 3. Agent与程序分工

协调Agent复用同一角色的两次有界调用：先提取GoalContract，最后整合建议。专家不拥有更完整的事实。

| 角色/节点 | 输入和输出 | 权限与必要性 |
| --- | --- | --- |
| 协调：目标提取 | 原需求/同任务问答、冻结公共家庭/偏好 → GoalContract或clarify/refuse | 不写设备；提取范围/例外/优先级。提取可能出错，必须单独评测并让用户确认实际方案 |
| 候选与预测程序 | GoalContract/精确冻结引擎 → 有界候选和数值证据 | 不消耗模型调用，不由模型编造温度/Wh |
| 舒适Agent | 同一GoalContract、公共事实、全部候选预测 → Advice | 候选ID、对首次达标/期限的判断、简短公开依据；不能修改硬目标 |
| 节能Agent | 与舒适Agent同事实/同候选 → Advice | 候选ID、同范围Wh取舍、公开限制；不能通过遗漏动作或改目标“省电” |
| 协调：方案合成 | 同一上下文+两份结构化Advice → 当前Plan或clarify/refuse | 对建议冲突按已明确偏好整合；不得把不满足硬目标的候选作为完成方案 |
| 程序校验/执行/核验 | Plan、绑定目标及最新家庭版本 | 再核对目标/期限/范围未漂移，保留/保护、能力、读数和参数；最终设备写入只有既有executor |

S1使用同一目标提取阶段、候选空间、预测结果、硬约束、最终Plan和执行器，只由一个规划角色完成建议整合。M与S1的规划角色均获得原用户原文/同任务公开问答，不只看提取后的GoalContract；专家可指出原文与契约不一致，返回clarify并停止，不自行改写目标。否则相同提取器遗漏的例外对专家也不可见，不能声称分工可以纠正它。M与S1获得同样资料，角色分工是主比较变量。

GoalContract最小字段：`room_id / climate_entity_id / cover_entity_id|null / target_temperature_c / ready_in_minutes / priority / allowed_fan_modes / cover_constraint / keep_entity_ids / protected_room_ids`。所有IDs来自当前家庭，priority只能comfort_first/energy_first；未明确则问。结构化UI保留项不得被目标提取遗漏，最终Plan与已保存GoalContract的温度/期限/对象集合必须一致。原始自然语言额外约束仍需解释评测和用户确认，不能声称程序已完全理解任意语言。

Advice最小字段：`role / outcome(recommend|clarify|refuse) / preferred_candidate_id|null / evidence_refs[] / public_summary`。引用只能来自本轮候选/目标证据；角色不调用数据库、URL、时钟或控制接口。非法Advice停止该轮，不能静默裁掉坏意见后称三角色协同成功。

实验最终输出用严格包装`Selection{candidate_id, plan: Plan}`或既有clarify/refuse；standard继续原OUTPUT，不直接给旧Plan塞额外字段。验证candidate_id存在、Plan精确对应其动作/GoalContract后，既有执行器只接Plan；绑定记录保存在版本化agent_run。这样可审计模型原选，不把程序映射/排序冒充专家判断。

## 4. 预测能力：精确隔离与可用边界

拟新增内部`forecast_plan`能力，所有实验模式共享。候选是单次绝对设置，复用现有控制参数和校验；本期最多4个候选（low/auto × 用户允许的窗帘开/合）。固定窗帘位置/保留窗帘时只保留该位置；硬指定风速只保留该风速。没有候选可按时达标时解释缺口并澄清，用户明确修改要求后重建目标，不能静默改为尽力执行。

1. 家庭短事务中同时取公共快照和私有精确引擎状态，随后释放事务再调用模型；预测上下文仅该轮内存持有。
2. 通过专用clone工厂复制rooms/entities/Decimal/故障/队列等状态，创建新锁；不能`deepcopy`整个RLock，也不能把公共0.1℃快照反序列化为精确物理状态。
3. 对目标房间的主温度、所有参与物理过程的启用窗户/占用输入进行可观测检查，两类物理感知至少各有一只可观测实体；涉及可控设备未知、离线、故障或pending动作时本期不给确定预测。缺窗户感知不能默认物理闭窗。首版目标房间只允许恰好一台启用空调、至多一只启用窗帘；即使用户能定位其中一台，其他参与物理过程的空调/窗帘也不能忽略，多实例返回forecast_unavailable和公开原因。
4. 克隆只执行已通过硬约束的候选，再推进1—1440仿真分钟。只返回目标作用范围的终点温度、首次公开读数达标时刻（初态已达标为0）、截止目标结果、范围内增量Wh、模型版本和依据版本。固定energy_scope_entity_ids为目标空调及存在的目标窗帘，包含实际帘动作能耗；未纳入的其他设备能耗不参与排序。精确累积再一次舍入。不返回私有中间状态或非目标房间的隐藏信号/能耗。最优只指本轮有限候选的等价最优集合，不代表全局最优。
5. 预测不修改真实家庭revision/时钟/动作/事件/能耗或数据库；异常也不回写。实际执行前仍检查world/config/revision。预测值明确标注仿真估计；实际核验沿用首次截止证据，不用预测替代。

预测最大候选数4、总模拟步数5760；克隆家庭至多16房间/256实体记录（含归档）、历史归档条目也须有界，超限返回不可用，不截掉物理输入。步数不等于CPU上界：advance会遍历家庭并生成快照，D2必须测最坏耗时/内存；受限线程执行与进程内并发槽隔离事件循环，分块检查单调时钟截止/取消信号，未完成结果丢弃。并发槽随实际worker结束释放，不能因等待方超时先释放而放入更多仍运行线程。线程不能硬杀，不得把异步wait_for说成CPU强制终止；此时仍仅克隆被计算，真实家庭不受写入。若最坏情况无法满足收尾余量，先降低上限。未来若增`forecast_plan`参数化tool call，要按各工具自己的Pydantic schema校验，现`EmptyArguments`只适用于两只读空参数工具，不能直接复用到预测参数。

## 5. 全栈接口、持久化及状态

沿用React/TS/AntD/TanStack Query、FastAPI/Pydantic/SQLAlchemy/MySQL、LangGraph为主/LangChain Core为辅、DeepSeek官方适配；不新增Redis、队列、向量库或供应商。LangGraph负责有界分支/并行/聚合，业务Task/Action承担持久记录；不称已实现图检查点恢复。

拟扩展`POST /tasks/agent`的可选`strategy`：`standard`（缺省，旧路径）、`single_forecast`（S1）、`expert_forecast`（M）。非标准策略下实际Task.mode为single_agent或multi_agent；strategy、pipeline_version及真实role记录公开可核对。实验能力通过config告知是否可用，未实现时不展示可执行入口。

幂等兼容：standard归一化时删除新增strategy键，保留旧的空keep/protected字段，使同体原键仍匹配旧request_hash；非标准strategy进入hash，换策略是新意图/新key。不能直接将新默认字段加入所有旧摘要。sessionStorage保存/校验新策略，旧无字段pending视standard；回复、确认、推进继续冻结body/key、GET恢复及busy保键。

Task.mode已有String列、agent_run已有JSON，本期设计复用，不先加数据库表/迁移。新JSON必须版本化并有界：goal、最多4预测、每角色公开Advice/issued calls/用量或未知/耗时/失败；公共快照、Plan、Action、deadline证据仍用既有字段。旧任务不回填专家意见。

前端和API要同时兼容rule/single_agent/multi_agent及混合历史；现有`check_turn`和`check_creation_replay`仅允许single_agent、前端mode联合类型/parseSummary/详情验证均须显式扩展，覆盖创建同键重放及同任务回答/确认。旧diagnostic的phase/output_kind/path白名单不直接塞入Advice错误，新增角色错误用有界role records/failure_code，既有方案校验诊断保持兼容。

零动作保护也必须扩展：现tasks.py的verify、TaskDetail核验按钮仅对single_agent阻止零动作失败任务；executor对空conditions可返回succeeded。新增multi_agent时，拒绝/超时/失败任务的后端重核验和UI必须同样阻止，不能将无执行证据的任务变成成功。规则任务原语义不改，advance已有统一零动作门禁仍需回归。

所有实验温控方案都必要确认，S1/M一致；低影响standard入口不新增确认。确认页显示实际目标、范围、候选差别、采用意见/取舍、预测与实测区别。执行后显示逐项读回/下一步，角色意见、调用量和阶段耗时折叠。没有真实节点事件就显示正在处理，完成后才回放真实角色记录，不造实时进度。

## 6. LangGraph、失败和预算

状态路径：目标提取 → 澄清/拒绝，或候选预测 → S1规划；M则并行舒适/节能 → 稳定按角色聚合 → 协调合成 → 共同校验 → 待确认 → 版本复查/执行/核验。角色状态不共享可变消息列表；每分支独立消息和结果槽，合并顺序固定，实际完成顺序不改变偏好判定。

每轮统一上限6次模型请求，整任务12次，最多3次澄清补答；标准旧路径保持原3次/轮语义。目标提取1次，两专家各最多1次，协调规划最多3次（含只读工具续调），合计最多6；S1目标提取1次、规划最多5次，共同上限6，不强制浪费额度。整轮65秒、单请求至多20秒且受剩余整轮时间限制，output≤2048 token/请求。65秒是截止，不承诺6个慢请求都能完成；超时按已发实际请求记账，未知用量不记零。现80秒Agent客户端/85秒代理先保留，另测服务端收尾余量。

专家格式非法/超时/预算耗尽，整轮停止、零设备写入，标analysis_incomplete及实际role；用户可显式新建standard任务，不能后台额外重跑再冒称multi_agent。一项意见不满足硬目标不参与可执行方案；偏好未定或硬条件互斥必须问用户。取消请求释放家庭占用并保存已发用量；没有用户取消按钮或自动恢复的能力声明。

候选排序器仅提供数值事实和独立oracle，不能在Agent选错后偷偷替换成最优再算模型成功。最终Plan绑定所选candidate_id和原始选择；硬条件违规拦截，合法但偏好次优保留其事实并按偏好指标判失败。本期实验确认前可用公开提示说明次优，不能无痕改成另一个选择。

角色并发共享每任务调用预算，使用异步原子预留；评测器另有跨进程/跨阶段共享授权账本，发送前落盘。未授权不发真实请求，D1零请求。

## 7. 分步验收和结果边界

D2先做隔离预测+增强S1离线闭环；D3做专家图+React/历史/恢复+MySQL/浏览器；D4在开发集真实评测和逐项调优；D5锁版本后运行新验收集/重复样本、交付真实比较。详见[交付顺序](../../product/product-d-delivery-plan.md)及[评测设计](../../product/product-d-evaluation-design.md)。

产品优先级：P0目标/例外不漂移、预测不写真实家、实际模式可审计、相同工具公平比较、无假成功；P1并行专家与用户确认、误拒绝/延迟/用量优化、可复现评测；P2自动策略路由、SSE、更多设备组合。多Agent收益、真实硬件节能、用户满意度、完整Figma在线交互仍无结果，不以设计文档勾成已实现。
