# HomeMind 产品 B：最小 AI 闭环设计补充

2026-10-27。用户在阶段 A 交付后“继续下一步”，授权依据已审阅 PRD 实现 B。本补充对齐原 M4 技术设计，不重复申请既有方向批准，不自动进入 C—E。

## 方案与取舍

沿用 M4 推荐的显式 LangGraph：受理/快照 → 单规划 Agent 与只读工具 → 结构化输出 → 全量程序校验 → 必要确认 → 共用执行器/核验器。模型仅套规则无法表达局部动作；自动循环写工具增加权限和恢复复杂度，均不采用。LangChain 提供消息和工具，供应商使用官方非思考 Chat Completions；适配器必须关闭隐式重试并忽略私有推理。

## B 的范围

自然语言支持三个场景、单设备局部动作、保留/保护、歧义澄清、明确拒绝。用户在原任务回答，最多三轮补充；每轮最多三次模型请求、六次只读工具、20 秒单请求/65 秒总限时、2048 输出 token。冻结公开家庭/偏好事实，调用期间不持数据库事务；执行前重读 world/config/state 版本，变化即阻断，不自动重规划。

复用 hm_tasks/hm_actions，迁移新增 mode 和 agent_run，旧记录为 rule。Agent 结果包含公开目标/方案、澄清、调用和时延等已发生记录；不存私有推理或供应商原始错误。规则/单 Agent 明确区分，模型未启用时保留规则入口。结构非法、重复/跨家庭/传感器写入、保留保护冲突、窗户打开/未知制冷、空计划均不发送设备动作。当前程序只能约束解析后的目标，不能宣称任意自然语言无误解。

确认采用明确的 waiting_confirmation 状态；全屋批量或覆盖不同的既有手动制冷设置时显示实际计划，确认必须匹配任务轮次，重放不再执行。简单低影响单灯操作不强加确认。waiting_input/失败无方案/未确认任务不可通过核验变成成功。

## 接口与产品连续性

- GET /tasks/agent/config、POST /tasks/agent、POST /tasks/{id}/reply：遵循 M4 的认证和每轮幂等；同键不同意图/模式冲突。同家庭业务运行互斥，不把模型调用期间变更的旧方案执行。
- POST /tasks/{id}/confirm：仅执行当前待确认方案，沿用同一 task_id，确认重复不得重发动作。
- POST /tasks/{id}/advance：仅演示开关启用且任务有可继续目标时操作；一个家庭事务内推进到目标分钟并立即核验。无截止的睡眠温度提供明确的 10 仿真分钟推进；已错过目标分钟不得补造历史证据，旧 world 拒绝。
- GET /tasks 支持家庭范围的提交键查找，优先只读恢复未知创建；详情增加 mode/agent_run/公开 plan。请求未知不换键自动重发。
- 前端保留现有浅色任务页，增加自然语言/规则入口和澄清/确认；按家庭隔离保存当前任务定位和未确认提交。刷新/重登录只读恢复，不自动执行；身份变化不展示旧家庭草稿。模型请求超时与代理超时覆盖 65 秒执行预算，普通接口仍用短超时。
- 普通模式无时间推进能力时，未来温度任务在创建/解析后说明并阻止执行，不制造永久等待任务；UI 明确仿真限制。

## 验证与交付边界

自动测试全部使用可控模型，不访问供应商；测试真实图分支、约束、幂等、并发/过期、澄清/确认、时间和账号边界。保留规则回归。独立 MySQL 验证迁移与持久记录；真实模型只做至多两次合成家庭能力检查，不执行真实家庭设备，也不把它记成十二场景效果评测。配置仅使用本项目 backend/.env，用户已有 API_KEY 只在本项目文件内适配，不读取旧项目或打印密钥。

Figma Starter 工具额度仍受限，不重复请求或绕过。必要交互先落地已有 React 页面并保存可核对的屏幕/状态规格，原稿交互连线和同步继续明确标待补齐；不声称本轮完成在线 Figma 编辑。多 Agent、批量真实模型效果评测、自动重规划、取消、SSE、检查点恢复和硬件仍未实现。
