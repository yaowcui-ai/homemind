## 目标与取舍

建立可追溯的「用户目标 → 场景/预期 → 实际运行 → 问题归因 → 改进」证据。候选方案为只加示例、直接扩多 Agent、场景验证后定向优化；本轮采用第三种。只加文案不能证明效果，多 Agent 尚无单 Agent 质量基线，故不提前进入 D。

扩展为至少 36 个产品案例，覆盖局部控制、生活联动、范围/例外、歧义/冲突、设备与读数故障、状态/网络/预算边界。每例注明用户目标、初始条件、输入、预期、需求、验证方式和完成状态。已有 DEV01—12 是历史开发集；新增 C 案例同样是开发验证，不冒充独立保留集或真实用户研究。

## 真实评测

在新的临时 SQLite 合成家庭内运行真实 FastAPI/鉴权/图/校验/执行/核验；不连接应用或测试 MySQL，不改用户家庭。模型是真实 DeepSeek，设备/时间仍仿真，SQLite 运行不能证明 MySQL 迁移。默认命令只列案例、不加载密钥、不联网；显式 `--real` 才启用。仅加载本项目模型配置，关闭继承追踪。

一个批次共享落盘预算，发送前先占用请求名额，已失败/超时请求也算。硬上限40，重启/复测不能重置。预算账本存在即拒绝新建覆盖，续跑读取原账本；每条完成即保存公开证据。只保留公开计划/对话/动作/读回/初末快照/用量与版本，不存原始供应商响应或私有思考。网络只允许官方模型端点。

优先跑明确单设备、回家/睡眠/离家、保留/保护、同名澄清、冲突、不支持动作、开窗/未知、离线/响应丢失等代表场景。预算不足的案例明确标未运行；不能用替身补齐真实结果。评分按运行前定义的目标和禁止改动集合，不用模型自己评分。分别报告指令理解、目标、联动、异常处置、调用与时延；阻断未执行和正确澄清不等于任务完成。所有分母、未跑与失败保留。若只得到小样本，不做泛化或单/多Agent优劣结论。

## 定向可靠性改动：推进响应未知

B 的创建/回答/确认已有原键恢复；推进仍是非持久操作，睡眠场景重发可能再推进10分钟。本轮补同家庭、同任务范围的持久推进幂等和时间前置条件。

- 新客户端提交世界ID、预期当前仿真分钟和独立幂等键；请求体/key冻结进入现有家庭 sessionStorage。
- 同键同体重放只读结果，不再次推进；同键异体拒绝。不同键但旧时间前置条件拒绝，防止跨标签或未知结果误推进。
- 事务内保存推进记录及状态，重建App/数据库连接后仍可查；重放先于当前world/deadline状态检查，读取历史不意味着向重置后的环境执行。
- 保留既有debug/归属/占用/温度目标/截止时刻检查。旧 `{}` API 若为兼容保留，明确无持久保证；新界面必须使用受保护契约，不能声称旧调用也具备新保证。
- 刷新只读任务，能确认原key已提交才释放pending；否则允许原体原键重试。5xx/网络未知不换键；只读恢复和迟到读写遵守B的selectionVersion/writeEpoch。
- 不补发设备动作，不改温度公式、截止证据或规则成功定义；不增加后台时钟、SSE、取消在途模型、自动重规划或多Agent。
