依据：[已确认总体设计](2026-10-26-homemind-system-design.md)、[M4 路线](../../homemind-development-roadmap.md)、[M3 接续](../../../CURRENT_CONTEXT.md)。本阶段由用户“现在继续下一步”发起，不推进 M5。

## 1. 目标和可见效果

用户在网页输入自然语言，系统根据当前账号的实际家庭配置提出结构化目标和动作，经程序检查后执行并独立读回。支持回家准备、睡眠、离家三个场景，也支持这些场景内明确限定的单设备动作，不把所有需求强行套入完整场景模板。

示例：

- “十分钟后到家，把客厅准备到 26℃。”：理解目标房间、温度和仿真提前量，规划灯/窗帘/空调，明确温度需要到目标时刻核验。
- “我要睡觉，卧室调到 25℃，保留阅读灯。”：其他房间不动，阅读灯进入保留集合；不能唯一定位阅读灯时先询问。
- “我要离家，关掉全屋灯和空调，卧室保持原样。”：范围由当前家庭发现，卧室受保护，不向受保护设备发送动作。
- “关闭客厅的灯。”：只对明确对象规划关灯，不附带关闭空调或窗帘。
- “准备一下。”或两个房间同名且未消除歧义：保存为待补充任务，展示问题；补充后继续原任务 ID。

“十分钟”指仿真分钟。本阶段没有后台计时器，不将现实时间经过当作仿真推进，也不承诺一定能在指定时间降到目标温度。

## 2. 架构选择

选择显式 `StateGraph`，LangChain 只提供消息、工具定义、结构化输出与必要的供应商适配器。

考虑过的其他方案：

1. 通用 Agent 自动循环：搭建较快，但执行路径和工具权限较难直观审查，不采用为本阶段主流程。
2. 模型仅解析三个规则模板：能较快复用 M3，但无法表达只关灯等局部要求，会混淆规则与单 Agent 基线，不采用。

推荐方案是一个规划 Agent，读取受限事实、提出结构化方案；确定性节点校验和执行。没有专业 Agent 分工、专业建议冲突或多 Agent 仲裁，它们属于 M5。

```text
认证与幂等受理 → 保存原始需求与家庭快照 → LangGraph
  读取家庭/偏好 → 模型规划 ↔ 只读工具
                        ├─ 请求澄清 → 保存 waiting_input → 返回问题
                        ├─ 无效输出/调用失败/超预算 → 保存失败 → 不执行
                        └─ 提交结构化方案 → 程序校验
                                               ├─ 歧义 → waiting_input
                                               ├─ 非法/状态已变化 → 失败，不执行
                                               └─ 统一执行器 → 独立读回 → 保存结果
```

## 3. 模型与配置

用户已选择 **DeepSeek 官方 API**。默认模型采用 `deepseek-flash`，API 地址 `https://api.deepseek.com`，M4 使用非思考模式（`thinking.type=disabled`）进行工具调用，降低编排复杂度。2026-10-27 核对官方文档：该模型当前由 DeepSeek-V4.1-Flash-1017 提供，支持工具调用与 JSON 输出。模型别名可能随供应商升级映射到新版本，验证记录应保存请求模型名及响应返回的实际模型标识（如有）。当前尚未配置或调用本项目真实密钥；不读取其他项目的密钥或隐式继承其他项目的供应商设置。

后端增加本项目配置：`HOMEMIND_MODEL_ENABLED`、`HOMEMIND_MODEL_PROVIDER`、`HOMEMIND_MODEL_NAME`、`HOMEMIND_MODEL_BASE_URL`、`HOMEMIND_MODEL_API_KEY`。密钥使用 `SecretStr`，只写入忽略的 `backend/.env`；示例文件只写字段说明与占位符。默认不启用模型。

先支持 DeepSeek，不扩展模型市场或浏览器端密钥设置。优先核对 `langchain-deepseek` 对所选模型及非思考参数的实际兼容性，在实现时锁定适配包版本；不能只按旧版集成文档中的旧模型示例判断。使用稳定 Chat Completions 接口及客户端 Pydantic 严格解析，不依赖 `/beta` 的服务端 strict 模式；JSON 输出支持不等于自动满足业务契约。供应商不保证输出通过本项目契约，解析失败仍须停止。模型名、API 地址与能力以官方文档和实际最小调用为准。

模型未配置时，网页显示“自然语言任务尚未配置模型”，规则任务与家庭控制继续可用；不自动用规则或测试替身冒充模型结果。

不启用远端追踪，不记录 Authorization、密钥、完整连接串、供应商原始错误正文或模型私有推理。界面和业务记录只保存任务相关的可公开目标、计划、简短依据和工具事实。

## 4. 工具和结构化输出

### 4.1 只读工具

`read_home` 返回受理时该家庭的房间、实体、合法能力、可观察状态及版本；`read_preferences` 返回本任务冻结的偏好版本和值。工具绑定已认证的家庭上下文，不接受模型传入的 `home_id`、SQL、任意 URL 或文件路径。

同一轮模型读取一致版本的快照。未知、离线、缺失的传感器保留 unknown，不泄露仿真引擎的不可观察内部物理状态。实体名称、用户文本和工具结果均作为数据，不能改变系统权限。

模型不能直接调用数据库、仿真调试、时间推进、reset 或原始设备写接口。写入只通过后面的程序执行节点。

### 4.2 输出契约

结构化输出只接受两类结果：

- `clarify`：一个明确问题和可供选择的实际房间/实体；不含可执行动作。
- `plan`：场景分类、目标房间、保留实体、保护房间、动作数组、温度目标/仿真期限，以及简短用户可见依据。

动作只允许绝对 `set_light`、`set_climate`、`set_cover` 及已实现参数。禁止相对 toggle、任意函数、虚构设备或修改传感器。计划中每个动作携带实体 ID、作用房间及预期参数，服务端按当前家庭事实重新生成显示名称，不信任模型填写的名称作为执行依据。

名称解析保留用户提到的名称和作用房间。若同名引用仍可能对应多个对象，不能任选第一项：进入澄清。用户已明确指定的保留/保护对象进入规范化约束，执行校验不能静默删除这些约束；明确冲突则询问，不自行选择优先级。结构化验证只能检查已解析的约束，不能保证模型对任意自然语言永远理解正确，界面需展示其理解与实际计划，验收包含误解和遗漏风险。

输出 Pydantic 契约拒绝额外字段、非法值和越界参数。无效结构、未知工具名或不合法工具参数会停止当前轮；不通过无限模型重试来掩盖无效输出。

## 5. 确定性校验与执行

M3 的规则规划与单 Agent 规划最终产生同一执行计划格式，共用 `executor.execute` 和 `executor.verify`。规则路径的已实现语义和历史不因接入模型改变。

执行前检查整个计划，通过后才能发送第一个动作：

1. 所有房间、实体属于当前家庭，实体已启用且未归档。
2. 引用无歧义，动作位于目标范围，保留实体和保护房间没有动作；不允许冲突/重复的实体动作。
3. 设备类型与参数匹配，传感器只读，温度/亮度/风速在当前能力范围内。
4. 制冷需要同房间可确认关闭的窗户。窗户打开或未知时拒绝对应制冷，展示约束原因，不虚构电动关窗能力。
5. 目标、期限和可核验条件对应，不接受空方案自动报告成功；缺少所需温度传感器时不能宣称温度已达标。
6. 执行前的 world/config/state 版本与规划依据相符；不符时终止本次方案并提示重新提交。本阶段不自动重规划，有限重规划属于 M6。

模型调用期间不持有家庭数据库事务或 MySQL 行锁。接收快照和执行回写分别使用短事务，执行事务内重新检查版本。沿用单 API 进程边界和家庭执行占用，规则/自然语言任务互斥执行；手动改动导致方案过期时必须终止旧方案。

设备响应与独立读回分别保存。响应丢失但读回匹配可确认动作，设备无效果不能算成功。未来温度目标复用 M3 显式时间推进/核验及 deadline 证据规则，目标未确认时显示等待/部分完成。

## 6. 澄清、幂等和持久化

继续使用 `hm_tasks` 和 `hm_actions`。迁移 `0003_m4` 为任务增加明确执行模式（旧记录回填 rule）与 Agent 运行 JSON，保存原始文本、澄清问答、结构化目标/方案、调用计数/用量、简短节点记录、失败原因和每轮幂等记录。既有 M3 快照与动作结构保留。

自然语言任务和规则任务列表都能标明实际模式；不从是否存在某段文本推定模型调用发生。

创建请求的幂等键按家庭隔离，同键同内容重放原任务，不再调用模型或重发动作；异内容返回 409。规则键与自然语言键在现有统一任务空间中不能互相重放成另一模式。

澄清回答使用独立轮次幂等键及预期轮次；同回答重试返回保存结果，过时/并发回答被拒绝。只允许 `waiting_input` 继续；补充后保留 task_id 和已有问答，重新读取当前家庭事实再规划。其他账号不能读取或继续此任务。

每次模型规划前提交任务状态；等待澄清不占用家庭执行。M4 通过业务记录重新构造下一轮图输入，不把它宣传为 LangGraph 检查点恢复或 `interrupt/resume` 持久恢复。进程中断后的活跃图自动对账/继续属于 M6；中断运行不得假报成功或自动重发未知动作。

## 7. API 与网页

### API

- `GET /tasks/agent/config`：已登录用户读取模型是否配置；只返回启用状态及公开模型标识，不返回密钥或完整配置。
- `POST /tasks/agent`：输入文本、预期 world_id、可选用户显式保留/保护项，使用 `Idempotency-Key`；返回统一任务详情。
- `POST /tasks/{task_id}/reply`：输入回答、预期轮次及本轮 `Idempotency-Key`，继续原任务。
- 沿用 `GET /tasks`、`GET /tasks/{id}`、`POST /tasks/{id}/verify`。新增静态路由置于动态 ID 路由前；待输入/无方案任务不能通过 verify 被误判成功。

全部入口沿用账号鉴权、CSRF、Origin、no-store 与家庭归属检查；不能只保护页面而遗漏 API。

### 网页

任务区域提供“自然语言”和“规则模板”两种明确入口。自然语言输入支持查看模型配置状态、需求提交、当前任务问题和回答、理解到的目标/保留项、最终动作、简短运行记录及核验结果。保留规则表单作对照。

不在本阶段重做整体网页视觉，不增加 SSE；请求期间显示正在规划，完成后展示已保存详情，可手动读取历史。跨视图保留未知提交的幂等键，同账号重新核对不丢失；切换账号清理输入、任务缓存和未完成请求，沿用 M3 的会话代次保护。

自然语言规划比规则任务耗时长，按单次总时限调整该入口的前端超时及 Vite 代理超时，防止现有 6/8 秒超时提前截断正常模型请求。请求结果未知时先读取原任务，不换键盲目再次执行。

## 8. 调用边界

每次提交/澄清轮次最多 3 次模型调用、6 次只读工具调用，单次模型请求最长 20 秒、该轮总时限 65 秒、输出上限 2048 token；关闭 SDK 隐式重试。最多 3 次澄清回答，总计至多 12 次模型调用。触限、超时或无进展即停止并保存明确原因，不执行未通过校验的方案。

输入文本每轮不超过 2000 字符，完整传入问答不超过 8000 字符；计划不超过 100 个动作，超过上限应说明范围限制。调用失败记录安全错误分类，供应商未返回 token 用量时为未知，不写成零；没有已核实价格时费用为未知。

真实能力检查最多 2 次模型调用，使用合成家庭数据，验证工具调用和严格解析；不操作用户家庭、不提交设备动作、不触发批量场景评测。真实场景演示是否额外调用需单独列出数量，不能混入自动测试。M9 再授权批量评测。

## 9. 验证和交付

### 默认自动验证（禁止外部网络）

- 使用可控模型替身测试 LangGraph 实际节点分支、只读工具、结构化验证和调用预算，不将替身结果写成真实模型效果。
- 覆盖三个场景与只关灯、动态改名/新增/删除实体、保留/保护、重名澄清及同任务继续。
- 覆盖非法参数、虚构/跨家庭 ID、传感器写入、窗户打开/未知、空/冲突计划、配置过期、模型超时/无效输出、未知工具、调用上限。
- 覆盖创建及每轮回答幂等、不同模式键冲突、同家庭并发、跨账号读取/回答拒绝、等待输入不能误核验成功。
- 前端验证提交中状态、澄清续接、网络结果未知后的同键重试、刷新只读历史、账号切换清理与手机宽度操作。
- 回归 M3，执行后端测试/静态检查、前端测试/类型/构建；独立 MySQL 检查新增迁移与任务/澄清持久化。

### 真实检查

只有用户在本项目配置好模型，且最小请求实际通过，才能写“真实模型接入通过”。配置缺失、鉴权失败或供应商能力不符都逐项记录，不以离线通过替代。

交付更新 README 的模型配置、启动、自然语言演示及常见错误；更新接续、路线和 M4 验证记录。区分代码完成、离线验证、MySQL 验证和真实模型验证。M4 不实现多 Agent、SSE、取消、自动重规划、检查点恢复、真实硬件或公网部署。
