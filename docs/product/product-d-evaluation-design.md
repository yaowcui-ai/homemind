## 1. 要回答的产品问题

在“按时达到温度，同时明确舒适/能耗偏好和不动项”的小范围任务中，专家分工是否减少目标/例外理解、方案取舍错误？用户是否值得为此多等、多消耗模型请求？允许结论是单Agent足够，或者多Agent更差。候选数值选优有确定性解，不能以算对四个数证明Agent架构必要。

| 组别 | 定位 | 公平控制 |
| --- | --- | --- |
| S0：当前standard | 旧产品/新增预测工具的次要消融 | 没有预测；不能将S0→M差异归因于多Agent |
| S1：single_forecast | 主对照 | 同目标提取阶段、原文/问答、家庭公共事实、候选及预测、动作/确认/核验；一个规划角色 |
| M：expert_forecast | 实验 | 同上述资料和工具，舒适/节能两专家+协调角色；如实记录更多调用 |
| O：确定性候选排序器 | 数值选择上界与oracle交叉检查 | 接人工目标契约和相同候选；不具备NL理解，不纳入端到端理解率排名 |

主比较仅S1对M。同供应商/模型别名、参数和输出上限，同精确初态、预测引擎版本、目标/硬约束、候选上限4、推进期限、版本门禁、每轮6/任务12模型请求、65秒截止。预算是共同上限，不人为让S1多调用。S0/O不消耗主试验模型额度，若要跑S0另先列范围。角色不得看到金标、评分器答案、未来实际结果。

两层拆开：E端到端从用户原文开始，提取错误仍记失败，不暗中换人工契约；P规划隔离层将同一人工契约直接提供两组，单测取舍/建议聚合，P不能充作自然语言理解准确率。两组规划均可回看相同原文，指出契约遗漏后应澄清，不能默默改硬目标。E/P的请求、结果与分母分开。

## 2. 最少必要指标与固定分母

| 指标 | 分子/分母与证据 | 不能怎样解释 |
| --- | --- | --- |
| 端到端目标完成 | 预标注可行、输入完整的E任务中：实际正确范围/硬约束、必要确认、逐项读回与首次deadline证据均符合的次数 / 全部此类已启动运行 | 模型拒绝、超时、脚本或系统错误均保留分母，另分原因；未启动因预算停止列未运行，不填成功 |
| 目标理解 | E任务中房间/设备/目标/期限/优先级/保留/保护语义全部正确的次数 / 全部适用E运行；缺信息预标正确应为澄清 | 不用对象名称关键词匹配；正确提取但执行失败不算整例成功 |
| 偏好一致的可行方案 | 完整可行任务中满足硬条件且按已定排序达到最优等价集合的次数 / 全部此类已启动运行 | 相同物理结果的多组参数可以都正确，不能只允许一个风速字符串；缺方案不从分母删除 |
| 异常处置 | 预标未知读数/互斥/不可行等任务中，原因与下一步正确且零越界写入的次数 / 全部预标异常运行 | 正确拒绝与成功执行分栏；只问了正确首句不等于补答旅程通过 |
| 时间与用量 | 每次API实际耗时、模型及工具/仿真耗时、issued calls、已返input/output tokens和unknown次数 | API时间排除真人等确认时间；完整脚本多轮时间另列。失败/超时也展示；小样本报原值/中位数/范围，不冒称稳定P95或费用 |
| 安全护栏 | 保留/保护/跨账号违规写入、目标与实际核验不符却宣称成功，逐次计数/全部已启动运行 | 零观察事件只是样本事实。受控回归与真实模型事件数分开，不能称100%安全 |

同范围/同期限Wh差异只在两组均真实执行并达到同一硬目标的成对样本报告，同时给全体完成分母；失败不因耗电0获胜。固定energy_scope_entity_ids为目标空调和存在的目标窗帘（含实际帘动作），不是无关房间或目标房间所有实体的总表；原始Decimal累积后再一次舍入，避免逐实体三位小数相加误差。首次达标用公开主温度读数，初态已达标记0，截止达标用首次deadline证据；都不是现实体感。解释只核对事实/证据引用，人工定性核对说明作者身份，不让另一个LLM偏好分替代实际目标。

候选最优只是本轮有限候选中的最优。记录Agent原选candidate_id及Plan，确定性排序器不能偷偷替模型换答案。硬约束违规应拦截；合法但偏好次优仍按原选择判偏好失败，即使页面提示用户重选也不能计作原方案正确。

每例另有一次整体通过布尔值：该例所有适用断言均过；不要将不同分母的目标、异常、补答平均成一个准确率。多设备成功只针对实际有两项以上动作的子集；不能将只有空调的任务灌进联动率。

## 3. 开发案例与场景价值

以下是开发草案，不是保留集，也不是已跑模型结果。基准F：默认客厅28℃/卧室27℃、窗户已知关闭、占用false、灯/空调初始off、窗帘100；客厅单空调、窗帘可合、目标26℃。保留其他房间，不添加灯动作。每例要保存完整初态而非只写“默认”。

| 开发例/输入示意 | 预期、判定依据和产品价值 |
| --- | --- |
| DD01：“20分钟后到客厅，26℃，优先尽快达到，可以合帘” | 合帘固定对照中auto第17分钟达标、low20分钟26.8；完整候选由D2逐个求值，不把这两行当四候选总排名。测硬期限先于能耗 |
| DD02：“60分钟后26℃，按时即可，优先少耗电，可以合帘” | 合帘low/auto均达标，low550.050Wh、auto850.050Wh；候选全集排序后执行。测节能不能破坏期限 |
| DD03：“60分钟后26℃，优先尽早达到，可以合帘” | 合帘auto17分钟、low41分钟；与DD02同事实不同偏好，测试是否理解取舍，而非永远选低风 |
| DD04：“20分钟26℃，必须低风，不许延时或调温” | 合帘低风不达标；必须先确认其他允许候选也不可行，再标澄清/零写。说明限制并问可放宽哪条，不能暗换auto |
| DD05：“60分钟26℃，优先少耗电，窗帘保持现在一半开，卧室/阅读灯不动” | 额外配置明确阅读灯并将帘设50；金标先实际重放候选再定，不猜可行。核对原文→GoalContract和保留设备无写入、无附带关灯 |
| DD06：“60分钟26℃，兼顾舒适节能”；窗户读数未知 | 先说明当前不可可靠预测、要求恢复读数，不接受口头“当作关了”。恢复后仍需澄清偏好；每次回答与是否真正提交分别计。若未走完仅报首轮结果 |

扩展交叉项：多/重名空调、未知非主占用、额外窗户、受保护目标房间、版本漂移、专家格式非法/超时、刷新/未知确认重试。程序故障注入先离线；真实模型主要测语言/取舍，不用模型预算重复测试锁。DD06等多轮案例按整任务12次上界估算，若轮次受限停止则如实记未完成。

D5在候选代码/提示词/工具冻结后另编12个独立验收输入，建议8个完整可行例+4个异常/缺信息例，覆盖偏好改写/保留项/读数缺口/不可行。预标金标契约、适用分母、期望首轮与脚本补答、允许候选/等价解及故障，再对输入+预期+初态JSON取SHA，**在运行前保存**。不要根据D4失败逐字改写形成“独立”集；重复既有模板的局限必须说明。金标仅评分器可见。

配对按同一精确初态克隆给S1/M，保留实体ID/物理顺序和无关设备初态，世界标识按隔离规则处理。按预定索引交替AB/BA执行，不能先全部跑S1后全部M；记录时间、供应商实际返回模型名、参数/提示词/源码hash。别名背后版本不可锁定时如实写限制。故障脚本相同；失败不临时换一个简单输入。每次确认/补答使用预先冻结脚本，不因知道某组计划差而帮它补更多信息。

建议预算分批，均为**未来建议、不是授权或实际请求数**：

| 批次 | 保守请求上界 | 约束 |
| --- | --- | --- |
| D4开发 | 72硬止 | 单任务≤12；含修复复测，先小批，额度不足保留缺项 |

## 5. 真实调优闭环和采用标准

先按失败发生处归因：理解契约、候选/工具资料、建议引用/聚合、硬门禁、执行或评分oracle。保存原失败、实际公开输出、精确初态和代码版本；发现评分错另存勘误，不能改旧评分伪装模型提升。例：C06证明漏标风速足以制造假失败。

每次只改一个主要因素，例如原文/例外提示、只呈现目标范围候选、Advice引用schema、并行超时处理。将变更前假设/验收写入迭代表；使用**开发例同条件配对复测**及对应程序回归。上下文裁剪要说明资料是否仍对S1/M相同；若只给某组额外资料，就改标条件，不能保留原公平结论。真实修复复测与旧首次结果分栏，不能合并挑最好一次。

验收集跑后不得继续调优又沿用同集声称独立验收；若修复则该集转开发并重建新验收集。报告原始逐例结果、两组胜/平/负、全部失败和未运行、调用/时间成本，重复样本单列。N小不作总体显著性/百分比提升宣传。

采用门槛先看护栏：观察到越界/假成功必须修复并新验收；再看目标质量的成对差异、失败原因与等待/用量。若M只是在同样成功下增加调用，没有可解释质量收益，S1保持默认、M保留实验；若有收益也只宣称覆盖场景的样本结果。用户可理解性仍需真人观察；代码/模型评测不能代替用户研究。
