# HomeMind 产品 C：真实开发场景评测与迭代报告

日期：2026-10-28，Asia/Shanghai。结论：本轮建立36个产品案例，完成18个真实模型场景的首批基线，并对一个失败案例做一次同条件复测。**初批符合验收13/18；不能据此宣称产品已达到稳定上线质量。** 多 Agent、第三方用户研究、真实硬件和正式保留集评测仍未开展。

## 1. 产品问题、样本与方法

验证的是：生活需求能否转成范围正确、例外保留、结果有证据的任务，以及失败后是否有下一步。[36例案例库](product-c-cases.md)由PRD与既有工程失败推导；C01—C18为真实模型候选，C19—C36为受控程序/交互回归。不是36个真实模型场景，也不是来自36名用户。

每例均在新建临时SQLite合成账号/家庭上，通过实际FastAPI、鉴权、LangGraph、只读工具、程序校验、共用执行器和独立核验运行。模型为真实DeepSeek官方`deepseek-flash`非思考模式；家庭设备、环境、能耗和时间仍为仿真。此批次不访问MySQL或日常家庭；MySQL迁移与持久化另有独立验证。

预先确定操作对象、参数、禁止修改集合、目标及异常行为；模型不能为自己评分。全屋方案只在匹配预标注方案后由脚本模拟用户确认，澄清回答为预定对象ID，用户思考时间为零。未通过的计划保留失败，不放宽约束。每场景首批运行一次，只有C04另复测一次，没有挑选最好结果。

用户授权硬上限40次模型请求，包含工具后的续调和澄清：初批38次，C04复测2次，**共40/40**。每次发送前先落盘计数，失败也占额；独占锁、固定授权批次及冻结版本阻止并发或换目录重置。复测明确新版本、沿用原账本和原案例摘要，原结果不覆盖。没有实际追加请求或估算费用。

## 4. 问题优先级与实际迭代

排序基于后果、核心流程和已观察证据，缺少用户频率数据，不编造RICE分数。

| 编号/优先级 | 发现 → 决定与修改 | 同口径验证及残余事项 |
| --- | --- | --- |
| BC01 / P1：范围和保留规划冲突 | C04/C06/C09三次真实错误；保留程序硬门禁，补充prompt定义：`room_ids`仅写入范围，keep不含动作目标，“其余不动”排除目标；不自动删约束或替模型修方案 | C04相同初始条件/原输入/原评分单次复测成功：只把客厅空调改低风、保留制冷/26℃、其他设备不变；2请求、10313ms。1次失败→1次成功，不能说明总体提升，C06/C09未真实复测 |
| BC02 / P1：互斥要求被拒绝但要求继续回答 | C12失败；prompt要求可由用户取舍的矛盾走clarify；旧失败UI明确已结束/未发动作，应开始新任务重提 | UI真实RED→GREEN，图/契约回归通过；C12新prompt尚未真实复测，不称已解决 |
| BC03 / P1：未知窗户的无效引用与解释不足 | C14失败；不将not_found强行改名成window_unknown，不据猜测删除检查 | 未修复/待定位；下一轮建议保留白名单内的被拒结构化计划/选项及字段定位，避免私有推理、加强未知状态语言样本 |
| BC04 / P0验收边界：推进响应丢失会再加10分钟 | 原B限制已知；新世界/时刻前置条件+持久原键记录，刷新只读查记录，原体原键重试；不同键旧时刻拒绝 | 6个后端边界、专用MySQL重新连接、2个真实浏览器受控故障场景通过；legacy `{}`无key仍无新保护，公开界面走新契约 |
| BC05 / P1：原请求未决、重试遇busy丢键 | 独立审阅真实RED复现：409 `home_busy`被当已知拒绝清pending；只对这类未决占用保留冻结key/body | 2条刷新分支及相关25回归通过，独立质量复核批准；没有声称所有4xx结果都未知 |
| EV01 / P1：评分器重复动作及澄清失败分母 | 审阅发现两个离线反例：重复实际动作可能掩盖缺项；C11失败可能掉出分母 | 修实际ID集合/唯一性，按预标注固定C11执行与异常适用性，RED→GREEN。原baseline评分保留，另存v2离线重评分；这18例的汇总没有变化，不增加模型调用 |

BC04以避免错误时间证据为P0验收要求，不把先前“可能重复推进”伪称成线上事故。BC01—03仍是进入稳定对照前的质量门槛；不能用新增多Agent掩盖它们。
