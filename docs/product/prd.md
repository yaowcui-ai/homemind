# HomeMind 产品需求文档 v0.3

日期：2026-10-28。阶段 A 定义、B 核心实现、C 首轮场景验证与可靠性。用户已确认采用产品阶段 A—E；需求价值尚未经过真实用户验证。[C 报告](product-c-evaluation.md)记录18个真实模型开发场景、5个失败及一个定向复测；独立保留集/单多Agent对照未开展。[B 验证记录](../verification/product-b-single-agent.md)保留历史接入与工程证据。

## 1. 产品定义和当前边界

**目标产品：将生活意图转成可解释、可核验联动任务的智能家居 AI 助手（仿真验证版）。** 核心价值是表达范围与例外、理解执行结果、在异常时知道下一步；不承诺真实节电、物理舒适度或现实定时控制。

当前已实现：账号独立家庭、可配置两房十二实体、手动控制、三类规则、偏好及任务历史；B 新增自然语言单 Agent、同任务澄清/必要确认、任务内时间引导/推进、未知提交只读恢复及公开计划/运行记录。业务状态经真实 API 和 MySQL 保存，设备、环境和时间为仿真；多 Agent、自动重规划和图恢复尚未实现。阶段 A 基线见 [历史审查](2026-10-27-ai-pm-positioning-review.md)。

沿用 React/Figma、Python/FastAPI/MySQL、LangGraph 为主和 LangChain 辅助的方向；不重新搭建控制台、数据库或设备接口。

## 2. 用户、问题和替代方案

候选核心用户：有灯光/空调/窗帘组合控制需求、希望表达临时例外的个人操作者；每账号一个家庭。是否具备足够频次和痛点仍待验证，不将求职展示需求等同于真实用户需求。

已知用户信息仅有 U01：项目本人自述“有少量设备，偶尔使用”。不能推定其设备类型、平台、联动习惯或代表性。尚无目标用户访谈或操作观察结果。

| 方案 | 适合的任务 | 本项目需要验证的取舍 |
| --- | --- | --- |
| 现有手动设备控件 | 明确、少量的设置 | 输入直接；组合任务需要多步操作 |
| 现有规则表单 | 稳定的回家/睡眠/离家组合 | 结果可预测；临时例外与局部动作表达受模板限制 |
| 已实现的自然语言单 Agent | 带范围、温度/时间和例外的需求 | 是否减少输入负担仍待观察；C已发现范围/例外误拒绝 |
| 计划中的按需多 Agent | 舒适与模拟能耗等多目标权衡 | 复杂场景质量收益能否抵消调用/延迟成本 |

以上是方案分析，不是已完成的外部竞品实测。需求假设、证据与研究方法见 [验证计划](validation-plan.md)。

## 3. 核心场景与范围

| 场景 | 用户目标与输入例 | 验收重点 |
| --- | --- | --- |
| 回家准备 | “60 个仿真分钟后到家，客厅准备到 26℃” | 理解房间/温度/提前量；动作与目标时刻温度分别核验 |
| 睡眠 | “准备睡觉，卧室 27℃，保留阅读灯” | 阅读灯必须真实存在并可定位；其他房间不动，不能从占用信号推断睡眠 |
| 离家 | “关闭全屋灯和空调，卧室保持原样” | 动作按当前配置生成，保护房间没有写操作，不能推断全屋无人 |
| 简单局部动作 | “关闭客厅主灯” | 只改指定灯，不附带执行整个离家模板 |

26℃/60 分钟只作为固定初始环境下的推荐演示案例，阶段 B 必须复测；不保证任意配置都可达。保留现有 26℃/20 分钟未达标反例，不改物理公式或成功定义。已有账号偏好不自动覆盖；新任务显示实际采用的温度、提前量和偏好来源。

首版允许六种已实现实体类型，控制仅灯/空调/电动窗帘，温度/占用/窗户为只读感知。温度目标沿用 16—30℃整数、提前量 1—1440 仿真分钟的能力边界。超出能力需解释或澄清，不静默取整、扩权或虚构制热/关窗能力。

不做真实硬件、门锁/燃气、摄像头识别、户型图/三维、家庭共享/多住宅、多个供应商平台、无限循环自治；高级恢复/SSE 仅在核心体验需要时加入最小版本。

## 4. 需求与优先级

优先级依据：先闭合核心任务并避免误操作，再验证多 Agent 收益，最后扩展。价值/成本为定性估计，不是假造调研分数。P0 是首版必要项；P1 是最终保留多 Agent 特色的作品必要后续。

| 编号 | 需求 | 现状与增量 | 优先级/成本 | 取舍依据 |
| --- | --- | --- | --- | --- |
| R01 | 家庭准备与能力检查 | 配置和执行前主读数/能力检查已有；统一准备提示仍可在 C 优化 | P0/低—中 | 先让用户知道哪些任务可执行，不重做配置向导 |
| R02 | 自然语言表达三场景和局部动作 | B 已接单规划 Agent 和统一执行路径；场景程序验证采用受控模型，完整真实理解效果待测 | P0/中—高 | 建立真正的 AI 产品核心 |
| R03 | 对象、目标及例外澄清 | B 已实现问题/实际选项/问答保存及原任务回答；同名、冲突与预算有程序回归 | P0/中 | 不用猜测范围代替用户决策 |
| R04 | 程序约束与分级确认 | B 已实现全量校验、过期阻断、单房/多房全屋确认及低影响短流程 | P0/中 | 失效方案不得直接写设备 |
| R05 | 动作/目标反馈与时间引导 | B 已在任务内展示时刻、下一步和原子推进/核验；普通模式有时间门禁 | P0/中 | 解决跨页与错过目标分钟的问题 |
| R06 | 当前任务与未知提交恢复 | B创建/回答/确认恢复；C增加带世界/时刻前置条件的推进持久幂等、刷新只读查记录、原键重试及busy保键；legacy空体推进无此保证，不含图恢复 | P0/中 | 刷新不等于重新发起任务 |
| R07 | 完整核心交互原型 | React 核心旅程已实现；Figma 既有页面/状态稿保留，在线新增状态/连线因额度仍待补 | P0/中 | 让需求可演练；额度受限时如实记录缺项 |
| R08 | 可观测结果与评测记录 | B 已保存公开方案、对话、调用/未知用量、规划/校验/执行耗时；正式评测运行记录后续采集 | P0/中 | 为效果判断留依据，不展示私有思维链 |
| R09 | 按需多 Agent 建议和协调 | 未实现；专业角色只读、统一执行器写设备 | P1/中—高 | 先证明单 Agent 基线，再验证多目标分工 |
| R10 | 真实用户观察与公平对照 | C已做18个真实模型开发场景及C04一次复测，40请求；访谈、独立保留集及单多Agent对照尚无结果 | P0设计/P1实测，中 | 不将开发样本或程序通过数写成产品收益 |
| R11 | 账号、配置、偏好和规则入口 | 已实现；后续继续回归，不改旧任务或自动恢复归档实体 | P0保留/低 | 当前可运行价值和对照条件 |
| R12 | 迭代与交付材料 | A 已建台账，B 追加真实问题/取舍/验证；完整求职包装仍留 E | P1/低—中 | 求职叙事与实际证据一致 |

## 5. 任务流程与交互契约

核心旅程：登录/注册 → 可跳过的家庭准备 → 选择规则/自然语言 → 输入需求 → 必要澄清 → 理解到的目标/范围/例外 → 分级确认 → 受控执行 → 动作读回与目标核验 → 结果及下一步 → 原任务/历史回看。

| 用户状态 | 应看到的内容和动作 | 当前实现情况 |
| --- | --- | --- |
| 请求处理中 | 已提交、正在处理；结果不明时先读取任务，保留原提交标识 | B 已实现，无虚构节点进度 |
| 等待补充 | 一个明确问题及实际对象选项，回答后沿用 task_id | B 已实现；公开问答永久保存 |
| 待确认 | 全屋批量/影响较大/覆盖已有手动设置时，展示实际范围与例外 | B 已实现 Agent 实际方案确认 |
| 动作已处理、目标待核验 | 当前/目标仿真时刻，哪些动作已确认、哪些环境条件还没有证据 | B 已实现任务内引导/受控推进 |
| 完成/部分完成/失败 | 逐项证据、未完成原因和可操作下一步 | B 已增加原任务读取/创建回答确认重试；更多 Bad Case 留 C |

没有真实节点事件时，只能显示“正在处理”，不能编造 Agent 已完成的阶段或进度百分比。规则/单 Agent/多 Agent 标明实际模式；模型未配置时显示不可用原因并保留规则入口，不用替身冒充真实模型。

时间契约：输入单位是仿真分钟。演示模式可以从原任务推进到尚未到达的核验时刻，然后独立核验；不能倒退补写已错过的读数。普通模式无推进器/后台时钟时，未来目标入口应禁用并解释限制，不创建无法继续的预约任务。不把现实等待包装成后台定时能力。

刷新/切页恢复先读取保存事实。未知提交只能查找或同意图同键重试，不自动生成新键重发。新的任务意图与原任务重试有明确区别；恢复定位和草稿按当前账号隔离。

## 6. AI、风险和异常策略

当前固定任务走规则，自然语言走单规划 Agent。阶段 D 才验证舒适/模拟能耗多目标是否需要专业建议：未来舒适和节能 Agent 只读，协调后仍经过同一校验/执行器；这一多 Agent 分工不是已有能力。B 实现依据为 [补充设计](../superpowers/specs/2026-10-27-product-b-design.md)，旧 M4 作为历史技术输入，不自动代表全部后续模块已实现。

权限、设备能力、参数、保留/保护和窗户条件是硬约束。用户硬性要求相互冲突时澄清，不能由模型默默降低优先级；软目标按已明确偏好取舍。窗户感知不具备关窗动作。

| 异常/风险 | 产品处理与验收边界 |
| --- | --- |
| 对象重名、指代不明、目标冲突 | 先问；没有写动作；回答后继续原任务 |
| 明确单设备、低影响合法动作 | 短流程，不为每次关灯增加冗余确认 |
| 全屋批量或影响较大 | 展示范围和例外后必要确认；确认后事实变更则旧方案失效 |
| 缺设备/主传感器或温度不可达 | 说明能力/证据缺口；可选设备不强加为必需，不虚构读数或承诺达标 |
| 窗户打开/未知，要求制冷 | 阻断对应违规制冷，解释原因和用户下一步 |
| 超时、格式非法、调用超预算 | 保存明确失败分类，停止；不执行未校验计划、不无限重试 |
| 设备离线、响应丢失、指令无效果 | 响应与读回分开；无法确认则保持未知/部分；核验不重发动作 |
| 跨家庭引用、归档/配置变化、环境 reset | 拒绝越权或失效方案；不复活实体、不自动复用旧事实 |
| 不支持的高风险设备/动作 | 拒绝并说明能力边界，不临时扩展类型或绕过检查 |

“按用户必需目标区分可选设备”用于新意图规划。现有规则模板对灯/帘/空调的固定要求继续明确展示；如要改变规则基线语义，须另记策略变更并回归，不能在对照评测时临时放宽规则成功条件。

## 7. 验收与指标

每个核心场景至少覆盖正常、例外/歧义、异常路径。原DEV01—DEV12和指标方法见[验证计划](validation-plan.md)；新增[36例产品案例库](product-c-cases.md)及[C实际结果](product-c-evaluation.md)分别标注真实模型、受控程序与待验证项。首批18例验收13/18，不能写成任务完成率或正式准确率。

阶段 B 的必要条件：真实模型接入有证据；三场景及局部动作能通过同一受控路径；例外不被改动；歧义会问；未知不算成功；目标等待可继续；刷新可定位原任务；未配置/调用失败有可用反馈；规则和账号既有流程不回退。Figma 与代码的完成状态分别记录。

产品指标包括目标完成率、理解准确率、动作读回成功率、异常处理正确率、约束违规/假成功、交互负担、分阶段时延及调用/用量。安全验收期望为无已知越权/违反明确例外/假成功，发现即阻断交付；有限样本通过不等于全局零风险。其余指标先建立基线，再决定改进门槛，不虚设已达成的准确率或节能比例。

## 8. 交付与待验证事项

阶段 A 完成产品定义材料，B 实现单 Agent 与核心旅程；这些不证明用户价值成立。后续 C 体验/可靠性 → D 多 Agent 对照 → E 完整作品；[正式路线](../homemind-development-roadmap.md)优先于旧技术编号的自然顺序。Figma 完整在线交互和真实产品效果仍须单独完成，不能因 React 可运行而勾选全部成果。

仍需用户研究验证：临时例外是否高频、自然语言是否比现有入口省操作、结果文案是否易懂、额外等待是否可接受；仍需真实模型验证理解与执行效果。设备平台竞品、市场规模、商业模式、线上增长不在本轮假定。
