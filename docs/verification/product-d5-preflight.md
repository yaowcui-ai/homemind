## 执行与停止规则

S1/M对每例及每次重复使用同一SQLite模板备份，包含同ID/世界/初态/物理顺序；按预定对索引交替AB/BA。应用照原模型选择确认；合法但偏好次优仍执行并记偏好失败，不能用oracle替换。沿用已公开的keep窗帘等价归一化，只规范评分副本，不改原Goal/Plan/动作。

独立新账本固定120共享请求，上限不是授权，也不保证36次全部完成；按单轮最坏6次计算，36次运行最多可能需要216次，因此120耗尽时保留未启动项。每次开始前至少留6次余量；发送前原子占额，失败、取消、未知用量均保留。仅给通用BudgetLedger增加显式`maximum`参数，默认仍40，D5同时显式传入limit=120与maximum=120；不改变HARD_LIMIT或旧账本。

`--real`必须验证已存在的完整冻结manifest，不能边跑边造新样本。续跑校验代码/提示源码、模型参数、顺序和所有模板；已完成跳过，已发送但无结果拒绝自动重放，不删账本、不换目录、不挑最好一次。脚本异常保存已捕获的任务/快照并停止，该次仍在所有适用指标的分母内；未启动列not_run。若模型或产品失败后修改候选，本集转开发，不能在同集调完声称新的独立验收。

异常的自由文本必须有语义核对。初始结构合格但语义未核对时标`pending`，不证明异常处置通过；仍保留适用分母，并单列待核对数。复核绑定问题SHA与完整证据SHA，另存复核者、理由及复核内容SHA；`--audit-reviews`写reviewed副本，保留原记录SHA、原评分与原始账本。作者AI辅助核对必须如实命名，不能写成独立人工评审。A09—12只验证首轮，尤其A10/A11没有恢复读数后完整温控覆盖。

首轮与重复分栏，端到端目标只对完整可行例适用；理解、异常、偏好、核验各自使用适用分母。Wh仅在两组均实际完成相同硬目标的配对中报告，固定目标空调+窗帘能耗范围；失败不能以0耗电获胜。原始记录包含API时间、角色/模型/工具次数、已知token与实际模型名，缺失用量不填0，不估精确费用或稳定P95。当前没有真实效果、M优势或总体提升结论。

## 命令

从仓库根目录运行；默认只列范围，不读取模型配置、不联网：

```powershell
backend/.venv/Scripts/python.exe scripts/product_eval_d5.py
```

本机已完成一次`--freeze`，不要覆盖或重建；仅在获得**新120次批次明确授权**后才执行：

```powershell
backend/.venv/Scripts/python.exe scripts/product_eval_d5.py --real
```
