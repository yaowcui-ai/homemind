## 如何让助手逐步开发

用户说“开始第 N 步”即授权助手完成对应阶段的实现、必要测试与修复。助手先读取本文件、系统设计和该项目最新接续记录，再检查实际代码状态，不从记忆假定上一阶段已完成。

每阶段的工作顺序固定为：

1. 说明本阶段目标、依赖、可演示结果和明确边界。
2. 将本阶段细化为可执行的小任务，确定要创建/修改的文件、接口、关键行为和验证命令，保存当前阶段实施计划。
3. 实现当前阶段；重要业务行为先用有意义的失败用例固定要求，再实现并验证。基础样式和说明文字使用适当检查，不为每个可逆小改动增加形式化测试。
4. 运行与变更相称的测试和构建，检查实际结果，修复本阶段发现的问题。
5. 给出简短交付说明：实现了什么、关键机制是什么、检查了什么、如何启动/演示、有哪些已知限制。
6. 更新本文件的勾选、证据和下一步。完成后停止，由用户启动下一个阶段。

不在每个文件或普通修复前重复询问许可；不在一个阶段里擅自完成后续全部阶段。若当前阶段遇到必须由用户提供的模型配置或设计取舍，说明具体缺项，先完成不依赖它的工作。

“继续”默认继续当前未完成产品阶段；完成后进入 A—E 的下一个阶段，M编号作为该阶段技术任务的索引。“检查第 N 步”只做核对与该阶段问题修复。“修改设计：……”先记录变更及其影响，再调整相关后续步骤。

各阶段可以跨多个聊天回合完成。遇到问题先定位原因，不将失败记录删掉后重新生成通过记录。

## M1 / 第 1 步：工程基础

**目标**：建立独立、可启动的网页和 API，为后续功能提供稳定入口。

**助手交付**：

- 独立 `homemind/` 项目目录与 Git 隔离方案，记录仓库边界，避免将旧项目改动纳入新项目。
- React、TypeScript、Vite、Ant Design 前端与 FastAPI 后端最小入口。
- Python/Node 运行要求、依赖锁文件、无密钥配置模板、基本代码检查。
- `/health` 活性接口、前端连通状态、开发启动说明。
- 对所选 LangGraph、LangChain 和 MySQL 检查点适配器做依赖兼容性检查，不声称已经验证数据库恢复。
- 创建项目自身的 `AGENTS.md` 和接续记录，写明本轮确定的按阶段委托方式。

**验收**：前端能打开，能从后端读到健康状态；基础检查与前端构建通过。配置缺失有可理解的提示。这个阶段不调用真实模型，不创建业务库，不伪装为已完成智能家居功能。

**用户指令**：`开始第1步，完成工程基础；验证并解释后停止，不提前实现第2步。`

## M2 / 第 2 步：可配置家庭与设备仿真

**目标**：在不依赖模型的情况下，获得可控制、可复现的家庭环境。

**助手交付**：可配置家庭、房间与实体模型；两房十二实体默认模板；六种类型的能力和动作；实例增删、改名与迁移；主传感器绑定；确定性的温度/能耗简化规则；可控时钟；状态和配置版本；保留配置的运行状态 reset；故障脚本；基础设备接口和简单操作页面。将物理参数、单位、时间步长及限制写入本阶段设计。此阶段使用显式演示家庭上下文，不公开为已支持账号隔离的服务；M3 接入数据库与认证。

**验收**：默认两个房间十二实体与实体设计一致；能修改灯、空调、窗帘并读回状态；能增添房间/第二盏灯并迁移设备；传感器对 Agent 只读，缺失/未知保留；能推进二十分钟，模拟离线与响应丢失。reset 保留用户配置，相同配置和输入序列产生相同状态。非法参数被拒绝，页面标注仿真数据及能耗模型。

**用户指令**：`开始第2步，完成可配置家庭、十二实体模板、设备仿真与基础操作页面，验证配置变更和故障行为后停止。`

## M3 / 第 3 步：账号隔离、业务持久化与规则基线

**目标**：建立任务与设备执行的业务闭环，不依赖语言模型也能验收。

**助手交付**：独立 MySQL Compose 服务和应用库、迁移；注册登录、Cookie 会话和必要写请求防护；每账号一个独立家庭和仅一次的模板初始化；房间/实体配置及环境/偏好/任务/动作/事件存储；全部已有接口的家庭归属检查；请求幂等；统一规则校验和动作执行器；家庭执行占用；三个明确模板的规则方案；基本注册登录页面和任务状态查询。

数据库资源必须新建且与旧项目隔离。初始化先检查新资源身份和状态，不以重建方式覆盖已有同名数据。调试所需随机凭据只保存在新项目本地配置中。

**验收**：两个账号得到独立模板和内部 ID；一方修改配置或关灯不影响另一方；伪造其他家庭、实体或任务 ID 的读写被拒绝，退出后不能操作。规则场景能经 API 执行并保存结果；重启后可读回用户配置、环境和历史；重复初始化不恢复已删除的设备；同幂等键不重复创建任务、不同内容拒绝；同家庭并发写任务不会交叉执行；无模型调用。

**用户指令**：`开始第3步，完成注册登录、独立家庭隔离、MySQL持久化和规则基线；不要修改其他项目的数据库。`

## M4 / 第 4 步：单 Agent 闭环

**目标**：自然语言需求能进入同一套受控设备执行路径，建立单 Agent 基线。

**助手交付**：模型适配、最小真实能力检查、工具定义、结构化目标/计划、单 Agent LangGraph、规则校验、执行核验、任务内澄清与同任务继续。测试默认使用可控模型替身；真实检查保持最小范围，批量付费评测到 M9 单独列明范围。

**验收**：三个场景各有功能演示；按当前家庭配置发现实体，不依赖固定房间名或数量；能保留用户指定例外；信息不足或同名实体无法定位时询问；缺少设备或传感器时不虚构能力和读数；结构化输出不合法时停止执行并给出原因；模型无法绕过归属与设备约束。真实接口配置不足时如实记录，不能用替身结果宣称真实接入通过。

**用户指令**：`开始第4步，用LangGraph完成单Agent自然语言闭环，LangChain只提供必要组件，验证后停止。`

## M5 / 第 5 步：多 Agent 协同

**目标**：让专业分工与冲突处理具备可观察行为。

**助手交付**：协调、舒适、节能三个 Agent；一致版本的输入快照；专业 Agent 只读工具；结构化建议和协调方案；简单任务短流程；多目标任务并行建议；单/多模式可切换并记录实际模式。

**验收**：能演示专业建议冲突及仲裁依据；明确卧室睡眠限制被遵守；简单关灯不调用所有专业 Agent；单 Agent 和多 Agent 共享执行器、设备事实和规则；计划中不存在两个专业 Agent 同时写设备的路径。

**用户指令**：`开始第5步，实现协调、舒适、节能Agent及按需路由，保留单Agent对照入口，验收后停止。`

## M6 / 第 6 步：状态变化与可靠执行

**目标**：面对过期状态、设备故障、未知结果和重启，系统给出可核验的处理结果。

**助手交付**：执行前状态核对；有限重规划；动作日志与读回核验；重试幂等；活跃执行/模型调用/重规划预算；取消；MySQL 检查点与业务记录对账；目标时刻到达后的继续核验。

**验收**：至少检查以下独立情形：计划后窗户打开；设备移除/迁移后旧计划失效；主传感器删除；设备离线；动作生效但响应丢失；成功响应但状态未变；执行中进程重启；等待核验时重启；重复提交；取消；模型反复无进展。检查点与恢复按家庭隔离；恢复不能重复已核验动作，遇到无法确认状态时必须保留 unknown/partial；没有证据时不声称 exactly-once 或所有故障自动恢复。

**用户指令**：`开始第6步，实现状态核对、有限重规划、故障处理和持久化恢复，用中断与未知结果场景实际验证。`

## M7 / 第 7 步：SSE 与实时控制台

**目标**：完整显示实际运行的家庭状态、协作进度和设备结果。

**助手交付**：按账号归属授权的持久事件流、SSE 事件编号与补发；前端去重、断线提示和重连；根据当前配置生成的房间设备卡片；房间/实体管理；任务交互、专业建议、最终方案和结果展示；电脑/手机响应式布局。

**验收**：页面展示来自后端事实；断开再重连不重新提交任务、不丢失已持久化事件、不因重复事件倒退设备状态；网页刷新能定位原任务。事件流异常与任务执行异常区分显示。

**用户指令**：`开始第7步，完成SSE与React实时控制台，验证断线、刷新和手机宽度操作。`

## M8 / 第 8 步：历史、偏好、配置体验与产品整理

**目标**：形成可持续使用的本地演示产品。

**助手交付**：只读历史与任务详情、偏好修改与版本保存、首次家庭配置引导、配置变更确认与主传感器选择；完善 M3 的账号会话体验；受控调试模式、清晰的错误与空状态。保持每账号一个独立家庭，不增加成员邀请和多住宅管理。

**验收**：新用户能使用模板并修改配置；移除设备和房间有明确作用范围，旧历史仍能回放；状态 reset 不覆盖当前配置；历史回放不调用模型；修改偏好不篡改旧任务；退出或切换账号后不能读取原账号任务、订阅其 SSE 或操作其设备；密码和模型配置不出现在浏览器或日志中；普通交付模式下故障注入/reset 不开放；手机端能完成关键操作。

**用户指令**：`开始第8步，完成历史、偏好、首次配置引导与界面整理，保持每账号一个独立家庭，不扩展成员共享和多住宅。`

## M9 / 第 9 步：冻结对照评测

**目标**：用数据回答多 Agent 在哪些任务上有收益，以及付出的代价。

**助手交付**：30 个开发场景、20 个保留场景，包含默认与用户修改配置后的任务；原始结果保存；配置/环境/评分条件版本；规则、单 Agent、多 Agent 执行入口；基于状态和动作的指标；完整对照报告。

真实批次运行前必须说明样本数、比较方案数、重复次数、调用上限和费用估算依据；若供应商价格或额度未知，明确缺项，不虚报精确费用。该阶段授权的批次按事先列明范围执行，不无限重试或临时扩大样本以获得更好数字。

**验收**：相同场景初始状态与故障脚本可复现；保留集运行前冻结；开发调优与保留评测分开；失败、未知用量和重复运行均保留；代表场景重复 3 次并报告波动；结果支持收益、无收益或部分任务退化的真实结论。

**用户指令**：`开始第9步，准备冻结场景和对照执行器，列明真实运行范围与预算后完成评测并保留全部结果。`
