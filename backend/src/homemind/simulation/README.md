# 仿真引擎与 M3 持久化约定

本包保留 M2 纯仿真引擎。M3 API 从认证家庭的关系记录重建私有引擎，在单进程家庭锁及 MySQL 行锁保护的事务中执行并保存；失败回滚不会发布私有状态。模板只在注册事务创建一次，读取不会补齐已归档设备。普通读取、配置和控制始终要求认证；环境事件、故障、推进与 reset 另要求显式启用调试。没有真实设备或模型调用。

模型版本为 `m2-decimal-minute-v1`。房间保存独立的内部热状态，逐分钟按设计公式计算，最后用十进制 ROUND_HALF_UP 保留 0.001℃，公开有效温度读数保留 0.1℃。功率与能耗都是演示假设，不能用于真实物理预测或节电结论。

- 所有已启用且未归档的占用信号按“任意一个有人”计算内部热增益；公开 `RoomView.occupied` 严格使用显式绑定的主占用传感器。没有绑定、离线或未知时公开值为 null。
- 内部窗户信号按“任意一扇打开”计算换热。缺失所有物理窗户/占用信号时，内部采用关窗/无人假设；公开读数继续为未知。观测质量不会抹去保存的物理信号。
- 离线故障与 available/known 只影响通信和读数，不会自动关闭已运行的空调或灯。停用或归档的实体不再参与后续分钟的物理模型和耗能。
- 多个窗帘的开度取平均，无窗帘时按完全打开；多个空调按不可变实体 ID 排序逐个制冷。每分钟被动热变化先发生，空调随后作用，温度在该分钟末统一舍入。
- 延迟动作在到期分钟 N 的边界生效，然后执行第 N 分钟的物理模型。它只依赖仿真时间，不等待真实时钟。故障持续到用户显式更改。
- 修改 config 更新保存的偏好；运行状态由控制接口或 reset 改变。reset 使用房间创建时保存的初温和实体当前保存的初始配置，不恢复默认清单。
- 世界总能耗包含当前世界内已归档设备此前耗能，避免删除设备使累计耗能下降；reset 清零当前世界总能耗。内部归档副本保留移除时的完整实体记录。
- revision 每次成功受理的变更增加；config_revision 仅随房间/实体配置操作增加。reset 改变 world_id，保留配置版本与 ID；事件序号持续递增，快照投影最多 50 条；持久事件表保留完整历史。

接口请求字段、能力、有限数值和额外字段均先验证，再在同一家庭事务内修改。非法请求不会产生部分状态、版本或事件变更。可选 expected_world_id 拒绝 reset 前的控制请求；旧任务在 reset 后只能读历史，核验说明环境失效。规则任务的动作意图和结果与纯仿真状态共同提交，不代表外部硬件的恰好一次语义。M3 没有模型、后台调度或 M6 执行恢复。
